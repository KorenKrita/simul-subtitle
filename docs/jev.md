# Jev 智能辅助（断句与译文检查）

[Jev](https://typesafe.ai) 是 TypeSafe 推出的云端结构化判断模型（System One Decisions Model）：它不生成自由文本，只对给定的自然语言状态输出带概率的结构化判断。

同传字幕利用 Jev 提供两项可选的辅助能力，**默认均关闭**，且两个开关彼此独立。

> **说明**：Jev 是 TypeSafe 的**闭源商业云服务**，并非开源项目。当你在设置中关闭这两个开关时，App 不会发起任何 Jev 网络请求。

---

## 两项辅助功能

### 1. 智能断句

- **判断问题**：“这段话说完了吗？”
- **工作机制**：
  - 开启后，每当分句器（`Segmenter`）遇到可能的句尾（静音停顿满 **0.4 s**，或单句持续满 **5 s**），会先将当前识别出的草稿发给 Jev 判断，最多等待 **1 s**。
  - 若 Jev 判断“还没说完”，当前句暂不定稿，继续等待说话人往下说；在 5 s 处被判定为未说完的句子，最长可蓄音至 **10 s** 再强制切分。
  - 若 Jev 判断“已说完”，或请求超时 / 出错，则立即按常规停顿定稿。

### 2. 检查译文

- **判断问题**：“这句译文有没有把意思译错？”（检测类别包括：凭空添加否定词、肯定/否定或转折关系译反、将比喻或直播惯用语按字面硬译等）。
- **工作机制**：
  - 每句**定稿**翻译完成后向 Jev 发起一次检查。
  - 当判错置信度达到 **0.6** 且属于可自动修正的错误类别时，流水线会附带针对性的修正说明，让翻译模型重新翻译这一句（每句最多重译一次）。
  - 开启后，定稿字幕的最终显示会略微延后（或先显示初稿、重译完成后刷新）。

## 接入服务与容错

| 服务渠道 | 是否需要 API Key | 说明 |
|---|---|---|
| **OpenCode Zen**（默认） | 不需要 | 免费公共接口；无需配置即可体验，但随时可能限速或停用 |
| **TypeSafe 官方** | 需要 | 官方直连计费接口 |
| **OpenRouter** | 需要 | 通过 OpenRouter 路由调用 `typesafe/jev-1.13`，按账户余额扣费 |
| **自定义** | 可以不填 | 自己填协议、服务地址和模型，例如 CLIProxyAPI 之类的本地代理；不填 key 时不发送 `Authorization` 头 |

### 自定义服务

1. 在「在线 Decisions 模型辅助」里打开「智能断句」或「检查译文」（两个都关时不显示服务选择），再在服务下拉里选「自定义」。
2. 选协议：
   - **TypeSafe System One**：路径 `/v1/systemone`，TypeSafe 官方、OpenRouter 和 CLIProxyAPI 都支持。
   - **OpenRouter Decisions**：路径 `/alpha/decisions`，OpenRouter 的 Decisions API。
3. 填服务地址。地址结尾已经是 `/systemone` 或 `/decisions` 时原样使用，否则自动加上协议的路径。输入框下面会显示实际请求地址。

   | 服务 | 协议 | 填的地址 |
   |---|---|---|
   | TypeSafe 官方 | System One | `https://api.typesafe.ai` |
   | OpenRouter | Decisions | `https://openrouter.ai/api` |
   | CLIProxyAPI | System One | `http://127.0.0.1:8317/v0/management` |
   | CLIProxyAPI | Decisions | `http://127.0.0.1:8317/v0/management/decisions` |

4. 填模型 ID 和 key（不需要 key 的服务留空）。
5. 点「测试连接」。它先保存，再发一次真实的句尾判断，显示「连上了」或服务返回的状态码和内容。

两种协议的请求和回答格式相同，App 按同一种方式解析。Decisions API 的「检查译文」回答里可以没有 `confidence`，这时取所选类别的概率。

- **数据与隐私**：仅向 Jev 发送本地识别出的**原文文本**与**译文文本**，不发送音频；自定义服务点「测试连接」时发送一句固定的测试日语。API Key 在 Android 存入 Keystore、macOS 存入钥匙串、Windows 经 DPAPI 加密，且不写入使用记录。
- **无感降级**：任何 Jev 请求超时、限流或网络失败，都会自动退回未开启 Jev 时的默认行为（按静音停顿断句、直接保留原译文），不会中断字幕。

## 请求频率与费用估算

### 触发频率

| 功能 | 触发时机 | 请求频率主要取决于 |
|---|---|---|
| **智能断句** | 每次可能的句尾（0.4 s 停顿或满 5 s） | 说话人的停顿密度（高于最终字幕句数） |
| **检查译文** | 每句定稿翻译完成后 1 次（重译结果不再复检） | 最终定稿的句子数量 |

两项同时开启时，请求次数直接相加（每次请求只评估一个问题）。

### 61.8 分钟直播实测数据

以下数据取自一次 **61.8 分钟**的日语 VTuber 直播实测记录（两项功能全开，使用 TypeSafe 官方接口，Token 统计取自接口返回的 `usage` 字段）：

| 功能 | 总请求数 | 平均每分钟请求 | 平均输入 Token / 次 | 平均输出 Token / 次 |
|---|---|---|---|---|
| **智能断句** | 1,031 | 16.7 次 | 603 | 20 |
| **检查译文** | 451 | 7.3 次 | 595 | 85 |
| **合计** | **1,482** | **24.0 次** | — | — |

由于输入 Token 中绝大部分是固定的问题定义与选项说明，单句原文和译文占比很小，因此单次请求的输入长度非常稳定（实测范围 540 ~ 737 Token）。

### 费用估算

Jev 官方定价按**输入 Token** 计费：**$0.042 / 百万输入 Token，输出 Token 免费**（参考 [TypeSafe 发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev) 及 OpenRouter 上 `typesafe/jev-1.13` 标价）。

基于上述直播实测数据折算：

| 开启状态 | 每小时输入 Token | 每小时预估费用 |
|---|---|---|
| **仅开启「智能断句」** | 约 60 万 | 约 **$0.025** |
| **仅开启「检查译文」** | 约 26 万 | 约 **$0.011** |
| **两项同时开启** | 约 86 万 | 约 **$0.036**（约合 ¥0.3 元/小时） |

> **补充说明**：
> - 语速越快、停顿越碎，断句请求越多；静音期间不产生请求。
> - 使用默认的 **OpenCode Zen** 渠道无需 API Key 也不产生费用，但属于非公开保障的公共端点。
> - 以上价格为文档撰写时的公开标价，实际费用以所选服务商的最新计费规则为准。
