# 翻译（BYOK）

同传字幕使用你自备的 **OpenAI 兼容接口（BYOK）** 进行实时翻译：服务地址、模型 ID 与 API Key 均由你自己提供，费用由对应服务商按你的实际 Token 用量收取。在「设置 → 翻译」的 LLM API 顶部可新建、重命名、删除和切换多套配置（每套独立保存地址、模型 ID、API Key、User-Agent 与自定义请求头；字幕运行中切换会从下一句开始生效）。

> 翻译请求仅发送本地语音识别转写出的**纯文本**与提示词，不发送任何音频数据。

---

## 对模型的要求

- **必须能关闭思考（深度思考 / Reasoning）**：实时字幕需要逐句低延迟返回，开启思考会让每句话多等很久。首次连接某个模型时，App 会自动探测关闭思考所需的参数并缓存（见下文）。
- **尽量选择响应快的模型**：正式翻译采用流式请求（`stream: true`），发出后 **5 秒内**未收到首字即判为失败，收到首字后整句最长等待 **8 秒**（断网或超时显示「翻译失败」，不自动重试）。模型响应越快，字幕越跟得上说话人。

## 协议与「关闭思考」自动探测

### 接口协议与安全策略

- **请求路径**：调用 OpenAI 兼容的 `POST {地址}/v1/chat/completions`（填入的地址末尾带不带 `/v1` 均可自动处理）。
- **鉴权头**：携带 `Authorization: Bearer {key}`；当 API Key 留空时不发送 `Authorization` 头（方便接入无需鉴权的本地或公共服务）。
- **安全约束**：仅接受 `https://` 地址，不允许包含用户名、`?` 查询参数或 `#` 锚点；请求**不跟随 HTTP 重定向**，防止 API Key 被重定向泄露到第三方域名。
- **凭据与日志脱敏**：
  - API Key 在 Android 经 **Android Keystore** 加密、在 macOS 存入**登录钥匙串**、在 Windows 经 **DPAPI** 加密保存。
  - 服务端返回的原始流式报文、思考内容、错误响应正文（可能回显 Key）一律不写入使用记录；仅记录剥离思考内容并抹除 Key 后的最终译文、HTTP 状态码、耗时与 `usage`。

### 自动探测关闭思考参数

各家服务商关闭思考的字段名称并不统一。首次使用某个「服务地址 + 模型 ID」组合时（点击「测试连接」或首次开始字幕），App 会用一句固定的日语依次尝试以下 7 种参数（每次最多等待 8 秒，均计为一次正常请求）：

| 探测顺序 | 请求体附加参数 | 常见适用服务 / 模型 |
|---|---|---|
| 1 | `thinking: {"type": "disabled"}` | DeepSeek、智谱 GLM、豆包等 |
| 2 | `chat_template_kwargs: {"enable_thinking": false, "thinking": false}` | vLLM / SGLang 部署的 Qwen3、DeepSeek 等 |
| 3 | `enable_thinking: false` | SiliconFlow、阿里云百炼（通义千问）等 |
| 4 | `reasoning: {"enabled": false}` | OpenRouter |
| 5 | `reasoning_effort: "none"` | OpenAI 推理模型、Gemini 的 OpenAI 兼容接口 |
| 6 | `reasoning_effort: "minimal"`，并在系统提示词末尾要求不思考、直接输出译文 | Gemma 4（如 Gemini 接口上的 `gemma-4-26b-a4b-it`）：只接受 minimal / high，minimal 下仍可能思考 |
| 7 | 不加额外参数 | 本身不带思考模式的常规对话模型 |

- **命中与缓存**：第一种**正常返回译文且未检测到思考内容**的参数会被记录下来，后续对该「地址 + 模型」的所有请求自动沿用（注：这代表该次响应未观测到思考输出，部分服务端也可能隐藏思考过程）。
- **思考内容判定**：响应中包含 `reasoning_content` / `reasoning` 字段、正文出现 `<think>` 或非空的 Gemma 思考通道 `<|channel>thought…<channel|>`，或 `usage.completion_tokens_details.reasoning_tokens > 0`，即视为仍开启了思考。这些标记包住的内容永远不会显示在字幕上；空的思考通道（Gemma 关闭思考时首包偶尔会带）不算思考。
- **异常与回退处理**：
  - 参数不被服务端接受（如 HTTP 400）时自动尝试下一种。
  - 遇到 Key 错误（401 / 403）、地址或模型不存在（404）、限流（429）或网络不通时立即中止探测并报错。
  - 遇到超时或 5xx 等不确定结果时不缓存结论，下次重新探测。
  - 若 6 种方式均检测到思考，会提示「关不掉思考，可能很慢」，但仍允许使用（思考内容不会显示为字幕）。

## 高级设置：自定义 User-Agent 与请求头

在翻译设置的 LLM API 下方展开「高级设置」，可自定义请求携带的 `User-Agent` 并添加最多 **20 个自定义请求头**（同时作用于实时翻译、测试连接与生成术语，不影响 Jev 请求）：

- **User-Agent**：留空时默认使用 `SimulSub/{版本号}`。部分服务商的公网防火墙会拦截未知客户端（常见如返回 HTTP 412），此时可按服务方文档填入指定标识。
- **自定义请求头**：每行填写一对名称与值（如 `X-Api-Key`）。名称仅限英文字母、数字及 `-`、`_` 等合法符号，值不可包含换行或中文；由客户端自身管理的保留头（`Authorization`、`Content-Type`、`Host`、`Content-Length`、`User-Agent`）不可覆盖。
- **加密与原子切换**：自定义请求头的值同样可能包含敏感凭据，因此与 API Key 一样加密存储，使用记录仅记录请求头名称（`byok` 事件中的 `mt_user_agent`、`mt_headers`）而不记录值。在高级设置弹窗点击「好」后再点击主面板的「保存」，整套配置会原子生效——字幕运行期间修改设置，会从下一句开始整体切换，不会出现新地址混用旧请求头或旧 Key 的情况。

### 示例：使用 B 站 Index 免费翻译接口

B 站提供了公开免费的 Index 专用翻译接口（无服务保障，可能随时限流、停用或调整规则），适合零门槛快速体验：

| 配置项 | 填写内容 |
|---|---|
| **服务地址** | `https://index-translate.bilibili.com/v1` |
| **模型 ID** | `Index-Translate-35B-A3B` |
| **API Key** | 留空 |
| **高级设置 → User-Agent** | `Index-Translate-Client/1.0`（必填，否则会被公网防火墙拦截） |

> 注：`Index-Translate-35B-A3B` 是纯翻译模型，用于实时字幕翻译效果良好，但不适合用来执行场景里的「生成术语」。

## 提示词结构与前缀缓存（Prefix Cache）

每次翻译请求的消息结构专为支持**服务端前缀缓存（Prefix Caching）**而排布，将整场会话不变的内容全部收敛在最前端：

```text
┌────────────────────────────────────────────────────────────────┐
│ system 消息（同一套设置下每句完全相同）                          │
│   • 翻译规则、源语言与目标语言要求                             │
│   • 当前场景的背景说明                                         │
│   • 整份场景术语表（仅当目标语言与术语表目标语言一致时附带）    │
├────────────────────────────────────────────────────────────────┤
│ user 消息（随每句动态变化）                                     │
│   • 【前文】最近 N 句已定稿的原文（仅用于理解指代与省略）       │
│   • 【当前句】本次待翻译的识别文本                             │
│   • 【注意】Jev 检出明显错译并触发重译时附带的修正说明          │
└────────────────────────────────────────────────────────────────┘
```

- **生成参数**：`temperature: 0`；单句最大输出上限：预设中文为 **160 Token**，其他语言为 **256 Token**。源语言选「不确定」时，提示词中写为「外语」由模型自行判断。
- **跨句前缀复用**：服务端前缀缓存只复用输入开头完全一致的连续 Token。把固定指令、背景说明与整份术语表全部放在 `system` 消息中，可以让不同句子之间最大化复用 `system` 前缀（各服务商是否支持缓存、最小触发阈值及缓存粒度以服务商文档为准；使用记录的 `mt` 事件会记录服务端回报的 `cached_tokens`）。
- **单句内本地复用**：同一句话在「草稿 → 定稿 → 重译」阶段若拼装出的完整提示词与上一次完全相同，客户端会直接复用上一次译文，不再发起网络请求。

## 结合上文（Context Window）

设置中的「结合上文来翻译」默认开启，默认参考最近 **2 句**（可调为 **1–5 句**或关闭；运行中修改从下一句起生效）：

- **仅收录非空定稿**：上文窗口只取最近几句非空定稿的**原文**，动态变化的草稿不会进入上文。
- **段内上下文锁定**：某一段话的上文窗口在它前一句定稿翻译完成时即固定下来，确保该段从草稿到定稿使用相同的提示词上下文。
- **延迟权衡**：参考句数越多，每次请求输入的文本越长，可根据模型响应速度酌情增减。

## 内容场景与术语表

在「设置 → 翻译 → 内容」中可选择「内容类型」，支持「编辑」当前场景或「新建」自定义场景。每个场景包含：
- **场景名称**（最多 20 字）
- **背景说明**（最多 1,000 字）
- **术语表**（最多 200 条；每条左侧填原文、右侧填译文，各最多 40 字，中间的 `→` 由 App 自动拼接）

### 内置场景

| 场景名称 | 背景说明 | 术语表 |
|---|---|---|
| **通用** | 无 | 无 |
| **B站 VTuber 直播** | B 站直播闲聊、念弹幕和 SC、原文来自语音识别（源语言非日语时自动将“日本虚拟主播”调整为“虚拟主播”） | `ビリビリ→B站`、`スパチャ→SC`、`配信→直播` 等 |

- 内置场景支持自行编辑，修改后可点击「恢复默认」还原；自建场景支持「删除」（删除当前使用中的场景会自动切回「通用」）。
- **术语表的目标语言匹配（`termsLang`）**：每个场景的术语表都绑定一种「译文是」的目标语言（内置场景为中文，新建场景时默认为当前字幕语言）。**只有当当前字幕目标语言与术语表语言一致时，才会将术语表放进提示词**；不一致时不会附带，界面下方也会明确提示「不会用上」。

### AI 辅助生成术语

编辑场景时点击「生成术语」，App 会调用当前配置的翻译接口，根据场景名称与背景说明自动列出该领域常见、易译错的词汇（条数上限可填 1–100，默认 20）：

- **只增不改**：已保存和正在编辑的术语保持原样；生成结果中与现有原文重复的词条会自动跳过，新词条追加在末尾，需点击「保存」后才会正式落盘。
- **格式清洗**：单次请求最长等待 1 分钟；自动剥离列表编号与符号，丢弃不含 `→` 或超长的无效行。

## 支持的语言

- **视频原声语言（原文）**：**日语**、**英语**、**不确定（日语或英语）**（受限于内置语音识别模型）。
- **字幕显示语言（译文）**：
  - **预设语言**：中文、英语、日语、韩语。
  - **自定义语言（「自己填…」）**：可填写任意语言或方言名称（最多 40 字，如 `法语`、`繁体中文（台湾用语）`、`粤语`），名称会原样写入翻译提示词与 Jev 检查问题中（内部保存为 `targetLang = custom:<名字>`）。
- **日译中专项调优**：仅预设列表中的「中文」启用专门调优过的日译中检查与修正提示及 160 Token 输出上限；通过「自己填…」输入的语言（即使填写“中文”）均按通用模板处理（256 Token 输出上限）。
